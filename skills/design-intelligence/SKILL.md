# 定位：视觉决策层，接在工程规范之上

**这份 skill 管「长什么样」，其他 skill 管「怎么实现」。**

- 它和 `ui-ux-decision-guide`（控件选型）不重叠：那个管「弹窗还是抽屉」，这个管「弹窗圆角多少、阴影多深」
- 它和 `react-frontend-architecture`（工程结构）不重叠：那个管目录分层，这个管 token 取值

**核心纪律：查不到依据就说不确定，不要编一个"好看"的数字。**

## 一、十类规则的影响优先级

**做 UI 时按这个顺序检查。** 优先级低的做再好，优先级高的不合格就是白做。

| 优先级 | 类别 | 影响 | 关键检查 | 常见错误 |
|---|---|---|---|---|
| **1** | **可访问性** | CRITICAL | 对比度 4.5:1、焦点环可见、键盘可达、图标有 aria-label | 去掉 focus ring、纯图标按钮无标签 |
| **2** | **触摸与交互** | CRITICAL | 点击区 ≥44×44、间距 ≥8px、操作有 loading 反馈 | 只靠 hover、状态切换 0ms 无反馈 |
| **3** | **性能与稳定** | HIGH | WebP/AVIF、懒加载、预留空间 CLS<0.1 | 布局抖动、图片撑开容器 |
| **4** | **布局与响应式** | HIGH | 移动优先、无横向滚动、不禁缩放 | 固定 px 容器宽、`user-scalable=no` |
| **5** | **导航** | HIGH | 返回可预测、底部导航 ≤5、支持深链 | 返回行为异常、导航层级混乱 |
| **6** | **排版与颜色** | MEDIUM | 正文 ≥14px、行高 1.5、语义色 token | 正文 12px、灰配灰、组件里写裸 hex |
| **7** | **动效** | MEDIUM | 时长分级、动效传达含义、支持 reduced-motion | 所有过渡同一时长、动 width/height |
| **8** | **表单与反馈** | MEDIUM | label 可见、错误就近、辅助说明 | placeholder 当 label、错误只在顶部汇总 |
| **9** | **图表与数据** | LOW | 图例、tooltip、不只靠颜色 | 只靠颜色区分系列 |

**冲突时的裁决**：可访问性 > 视觉美观。**对比度不够的"好看"是缺陷，不是风格。**

## 二、设计 tokens（后台系统的基础表）

**所有视觉决策落在 token 上，不在组件里写裸值。**

### 2.1 颜色

```
主色 brand        #1677ff（AntD 默认）或品牌色
语义色
  success         #52c41a
  warning         #faad14
  error           #ff4d4f
  info            #1677ff

中性色（文字 4 级）
  text-primary    #000000e0   正文
  text-secondary  #000000a6   次要说明
  text-tertiary   #00000073   占位、禁用
  text-disabled   #00000040

边框 2 级
  border          #d9d9d9
  border-secondary#f0f0f0

背景 3 级
  bg-container    #ffffff     卡片
  bg-layout       #f5f5f5     页面
  bg-elevated     #ffffff     弹层
```

**语义色不能当分类色用**——红色永远表示"坏"。

### 2.2 主色的 10 级色阶

```ts
// AntD 自带生成器，不要手调
import { generate } from '@ant-design/colors'
const palette = generate('#1677ff')   // [ '50', '100', ... '1000' ]
```

| 用途 | 级别 |
|---|---|
| hover 底色 / 浅背景 | 50 / 100 |
| 边框（激活态） | 300 |
| **主色（按钮、链接）** | **500 / 600** |
| 按下态 | 700 |
| 深色文字（在浅色底上） | 800 |

### 2.3 字号阶梯

```
12  辅助信息、表格内标签
14  正文默认（后台系统主字号）
16  强调正文、表单输入
20  页面内区块标题
24  页面标题
32  数据大屏主数字
```

**后台系统正文用 14，不是 16。** 16 是营销页的默认值，后台信息密度高，14 更合适。**但移动端必须 ≥16**（防 iOS 放大）。

**字重只用三档**：400（正文）/ 500（强调）/ 600（标题）。不要出现 300 或 700+。

### 2.4 间距（4 的倍数）

```
4   元素内极小间距（图标与文字）
8   紧密相关元素
12  表单字段内部
16  常规间距（卡片 padding）
24  区块间距
32  大区块分隔
48  页面级分隔
```

**没有 5px、10px、15px。** 全用 4 的倍数，视觉节奏才稳。

### 2.5 圆角

```
2   标签、徽章
4   小元素
6   按钮、输入框（默认）
8   卡片、弹窗
12  大容器（抽屉顶部，移动端 sheet）
```

**同一层级用同一个圆角**——按钮 6、输入框 6、卡片 8，不要混。

### 2.6 阴影（3 级，不要更多）

```css
--shadow-1: 0 1px 2px rgba(0,0,0,.03), 0 1px 6px -1px rgba(0,0,0,.02);   /* 卡片默认 */
--shadow-2: 0 6px 16px rgba(0,0,0,.08), 0 3px 6px -4px rgba(0,0,0,.12);  /* 悬停、下拉 */
--shadow-3: 0 9px 28px 8px rgba(0,0,0,.05), 0 6px 16px rgba(0,0,0,.08);  /* 弹窗、抽屉 */
```

**不要用大范围模糊的"毛玻璃大阴影"**——后台系统里会显得脏。

## 三、三个调节参数

定视觉方向时用这三个维度，比"好看一点""现代一点"可执行。

| 参数 | 低（1–3） | 中（4–7） | 高（8–10） |
|---|---|---|---|
| **密度** | 宽松，间距 24–96<br>营销页、引导页 | 常规，16–64<br>一般后台 | 密集，8–32<br>数据大屏、监控台 |
| **对比** | 柔和，浅灰底、低饱和<br>消费级、内容站 | 常规，白底、标准对比 | 强对比，深色为主<br>开发者工具、监控 |
| **动效** | 微交互 100–150ms<br>工具型产品 | 标准 200–280ms<br>多数后台 | 编排 300–400ms<br>品牌站、展示页 |

### 后台系统的默认值

```
密度 8    —— 后台是数据处理工具，信息密度高
对比 6    —— 白底常规，不用过度设计
动效 4    —— 只做必要的状态反馈
```

### 用法

新项目开工时，先确认这三个值，再定 token：

```
"这是个数据监控台" → 密度 9 / 对比 8 / 动效 3
"这是给客户看的 SaaS 后台" → 密度 6 / 对比 5 / 动效 5
"这是内部运维工具" → 密度 9 / 对比 4 / 动效 2
```

## 四、设计系统持久化（MASTER.md）

**设计决策必须写入文件**，否则跨会话就丢了，每个页面各定一套。

```
design-system/<project-slug>/
├── MASTER.md              全局唯一真相
└── pages/
    ├── dashboard.md       页面级覆盖
    └── order-list.md
```

### MASTER.md 的最小内容

```markdown
# <项目名> 设计系统

## Dials
密度 8 / 对比 6 / 动效 4

## 颜色
主色 #1677ff   语义色 见 AntD 默认
中性色 见 token 表

## 字号
12 / 14 / 16 / 20 / 24 / 32，正文 14

## 间距
4 的倍数，卡片 padding 16，区块间距 24

## 圆角
按钮 6 / 卡片 8 / 弹窗 8

## 风格
AntD 默认（圆角 6、蓝色主调、克制阴影）

## 禁止
- 玻璃拟态
- 自定义字体
- 超过 3 档阴影
```

### 检索规则

```
1. 先读 MASTER.md
2. 有 design-system/<project>/pages/<当前页>.md → 用覆盖
3. 否则用 MASTER
```

**改 MASTER 必须显式确认**，不能静默覆盖——里面可能有用户或同事定过的决策。

## 五、后台系统只有 4 种可用风格

不要从"79 种设计风格"里挑，后台系统能用的就这些：

| 风格 | 特征 | 适用 |
|---|---|---|
| **AntD 默认**（90%） | 圆角 6、蓝色主调、克制的阴影、系统字体 | 绝大多数后台 |
| **密集数据型** | 行高 36–40、字号 12–14、间距 8、边框细分隔 | 大表格、监控台、金融 |
| **品牌化 SaaS** | 主色跟品牌、圆角 8–12、有插画与空态图 | 对外产品 |
| **深色优先** | 深灰底 `#141414`、低饱和、发光强调 | 监控、开发者工具 |

### 明确不要用的

| 风格 | 为什么不适合后台 |
|---|---|
| **玻璃拟态（Glassmorphism）** | 半透明背景在数据密集页面里看不清文字 |
| **新拟态（Neumorphism）** | 对比度天然不足，违反可访问性 |
| **粗野主义（Brutalism）** | 高对比撞色 + 大字，不适合长时间处理数据 |
| **3D / 拟物** | 装饰性太强，干扰信息读取 |

**判断标准：这个风格能让用户连续看 8 小时不累吗？**

## 六、配色方法（四步）

```
① 定主色
   有品牌色用品牌色；没有就用 #1677ff
   用 @ant-design/colors 的 generate() 生成 10 级

② 语义色固定
   success #52c41a / warning #faad14 / error #ff4d4f / info 主色
   这些不随品牌变

③ 中性色
   文字 4 级 + 边框 2 级 + 背景 3 级（见 2.1）
   不要自己调灰，用 AntD 的 opacity 体系

④ 检查对比度
   正文对背景 ≥ 4.5:1
   大字（≥18px 或 ≥14px 加粗）≥ 3:1
   用 WebAIM Contrast Checker 验
```

### 深色模式的独立色板

**不要把浅色模式反色**：

| 项 | 浅色 | 深色 |
|---|---|---|
| 页面底 | `#f5f5f5` | `#000000` |
| 容器底 | `#ffffff` | `#141414` |
| 主文字 | `#000000e0` | `#ffffffd9` |
| 边框 | `#d9d9d9` | `#424242` |
| 主色 | `#1677ff` | `#1668dc`（降饱和） |

深色下**饱和色要降一档**，否则刺眼。

## 七、字体与数字排版

### 7.1 后台系统用系统字体

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Microsoft YaHei", sans-serif;
```

**不要引入自定义字体**：多一个网络请求、有 FOUT、中文子集化很麻烦。品牌站才需要。

### 7.2 数字要用等宽

```css
.tabular { font-variant-numeric: tabular-nums; }
```

**表格里的金额、数量、ID 必须用**，否则数字宽度不一，列对不齐。

### 7.3 中英混排

- 中文行高 1.6–1.75（英文 1.4–1.5）
- 中英文之间**不加空格**（前端渲染时浏览器会处理，不要在文案里手打）
- 数字与中文之间**要有间距**（用 CSS `letter-spacing` 或直接排版时留）

## 八、AntD token 定制（可直接用）

```tsx
<ConfigProvider
  theme={{
    token: {
      colorPrimary: '#1677ff',
      borderRadius: 6,
      fontFamily: '-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif',
      fontSize: 14,
      controlHeight: 32,
      wireframe: false,
    },
    components: {
      Table: { headerBg: '#fafafa', rowHoverBg: '#f5f9ff', cellPaddingBlock: 12 },
      Card:  { paddingLG: 16 },
      Button:{ controlHeight: 32, paddingInline: 16 },
    },
  }}
>
```

**密度高时**：`controlHeight: 28`、`cellPaddingBlock: 8`、`fontSize: 13`。
**品牌化时**：`borderRadius: 8`、`controlHeight: 36`、`fontSize: 15`。

## 九、交付前检查清单

**按优先级顺序过一遍**，前面不过不要看后面。

### 可访问性（P1）

- [ ] 所有正文对比度 ≥ 4.5:1，大字 ≥ 3:1
- [ ] focus ring 可见，没被 `outline: none` 去掉
- [ ] 所有交互元素键盘可达，Tab 顺序合理
- [ ] 图标按钮有 `aria-label`
- [ ] 图片有 `alt`（装饰性图 `alt=""`）

### 触摸与交互（P2）

- [ ] 点击区 ≥ 44×44（移动端）/ ≥ 32×32（桌面）
- [ ] 相邻点击区间距 ≥ 8px
- [ ] 所有异步操作有 loading 反馈
- [ ] 没有只靠 hover 才显示的关键信息

### 性能与稳定（P3）

- [ ] 图片用 WebP/AVIF，有宽高或 aspect-ratio
- [ ] 列表有骨架屏，加载不跳动（CLS < 0.1）
- [ ] 路由级代码分割

### 布局与响应式（P4）

- [ ] 无横向滚动
- [ ] 不禁用缩放（`user-scalable=no` 只在特定场景）
- [ ] 1280 / 768 / 375 三个宽度都看过

### 导航（P5）

- [ ] 浏览器返回行为符合预期
- [ ] 深层页面有面包屑
- [ ] 当前所在位置有明确高亮

### 排版与颜色（P6）

- [ ] 正文 ≥ 14px，行高 ≥ 1.5
- [ ] 没有组件内写裸 hex
- [ ] 数字用 `tabular-nums`
- [ ] 字重不超过 3 档

### 动效（P7）

- [ ] 时长符合分级（上限 400ms）
- [ ] 支持 `prefers-reduced-motion`
- [ ] 没有动 width/height

### 表单与反馈（P8）

- [ ] 每个字段有 label
- [ ] 错误显示在字段附近
- [ ] 有辅助说明（help text）

### 图表与数据（P9）

- [ ] 有图例与 tooltip
- [ ] 不只靠颜色区分系列
- [ ] Y 轴有单位

## 十、UX 硬规则速查（按严重度排序）

以下每条都是「违反了就是缺陷」级别，不是风格偏好。

### Critical（4 条，不可妥协）

| # | 规则 | ✅ Do | ❌ Don't |
|---|---|---|---|
| 1 | **对比度** | 正文对背景 ≥ 4.5:1，大字 ≥ 3:1 | 浅灰文字配白底、低饱和撞色 |
| 2 | **键盘可达** | 所有交互元素 Tab 可达、顺序合理 | 用 div 做按钮、`tabindex="-1"` 藏关键操作 |
| 3 | **焦点不被遮挡** | sticky 头部留出焦点滚动空间（`scroll-margin-top`） | 焦点元素被固定头部盖住 |
| 4 | **最小点击尺寸** | 触屏 ≥ 44×44，桌面 ≥ 32×32 | 16px 的图标当按钮 |

### High（后台系统最常犯的 17 条）

| # | 规则 | ✅ Do | ❌ Don't |
|---|---|---|---|
| 5 | **焦点可见** | 自定义 focus ring（`box-shadow`） | `outline: none` 而不给替代 |
| 6 | **不能只靠颜色** | 颜色 + 图标/文字/线型 | 红绿两个色块表示状态 |
| 7 | **输入框有 label** | 每个字段有可见 label | placeholder 当 label |
| 8 | **错误就近显示** | 错误紧跟字段下方 | 所有错误统一堆在页面顶部 |
| 9 | **提交反馈** | 按钮 loading + 结果提示 | 点了没反应 |
| 10 | **确认弹窗** | 破坏性操作二次确认并说明后果 | 直接执行删除 |
| 11 | **无横向滚动** | 内容自适应容器宽度 | 固定 px 宽容器在小屏溢出 |
| 12 | **不禁缩放** | 允许用户缩放 | `user-scalable=no` |
| 13 | **正文可读** | ≥ 14px（移动端 ≥16px） | 12px 正文 |
| 14 | **内容不跳动** | 图片预留宽高、骨架屏行数匹配 | 加载完内容撑开（CLS > 0.1） |
| 15 | **z-index 有层级表** | 定义 dropdown 1000 / sticky 1100 / modal 1300 / toast 1400 | 随手写 `z-index: 9999` |
| 16 | **hover 不是唯一交互** | 触屏用 click/tap | 关键信息只在 hover 时显示 |
| 17 | **loading 有反馈** | 骨架屏或 spinner，延迟 300ms 显示 | 空白冻结 |
| 18 | **尊重减少动效** | 支持 `prefers-reduced-motion` | 忽略系统设置 |
| 19 | **动效克制** | 一屏最多 1–2 个进场动画 | 每个元素都 animate |
| 20 | **返回行为可预测** | 保留浏览历史 | 用 `location.replace` 破坏后退 |
| 21 | **长 token 可断行** | URL、哈希、长 ID 用 `word-break: break-all` 或 `overflow-wrap: anywhere` | 长串撑破容器 |

### 专业级补充（容易被忽略，但在评审里会被指出）

| # | 规则 | 说明 |
|---|---|---|
| 22 | **关键文本不截断** | 截断必须保留完整版本的访问路径（Tooltip / 详情页），不能只 `ellipsis` 了事 |
| 23 | **文字可重排** | 用户放大到 200% 或加大字间距时，内容不丢、不重叠 |
| 24 | **状态切换可取消** | 快速连点时，前一个过渡能被打断，不排队播放 |
| 25 | **不能只靠拖拽** | 拖拽排序/滑块必须有键盘或按钮替代 |
| 26 | **认证不靠记忆** | 登录/验证不能强制用户记忆或解谜，支持密码管理器粘贴 |
| 27 | **轮播可暂停** | 自动轮播的内容必须能暂停，且默认不自动播放 |
| 28 | **错误汇总可聚焦** | 表单顶部错误汇总要能 Tab 到，并跳转到对应字段 |
| 29 | **紧凑组件的语义** | 小尺寸 chip/badge/图标按钮必须有 `aria-label` 或可见文字 |
| 30 | **badge 更新可感知** | 未读数变化时用 `aria-live="polite"` 播报，不要静默变更 |

### 用法

- **评审 UI 时按 1→30 顺序过**，前面不过不要看后面
- 这 30 条与 `ui-ux-decision-guide`（选什么控件）互补，不重复

## 十一、反面清单

1. ❌ 为了"好看"降低对比度
2. ❌ 后台系统用玻璃拟态 / 新拟态 / 粗野主义
3. ❌ 组件里写裸 hex（`color: #1890ff`）
4. ❌ 间距用 5px / 10px / 15px
5. ❌ 字重出现 300 或 700
6. ❌ 引入自定义字体（后台系统）
7. ❌ 表格数字不用 `tabular-nums`
8. ❌ 深色模式直接反色
9. ❌ 阴影超过 3 级
10. ❌ 设计决策不落盘，每个页面各定一套
11. ❌ 视觉方向只说"现代一点"而不给参数
